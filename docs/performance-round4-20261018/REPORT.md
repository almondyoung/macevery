# MacEvery 第四轮短词查询与元数据压缩

日期：2026-10-18；版本：r2，受控验证完成，候选 App 已构建；等待解锁完成安装和原生验收。

基线为第三轮主干 `4c17a03f805a40b0d11c025d8f66b82650cc92df`，安装源码为 `d93f3f6`。用户授权验证通过后替换本机 App、提交和推送；保留 0.1.3，以 Git SHA 标识开发包，不分配正式版本或 tag。

## 变更与原因

- 第三轮 1–7 字节短词仍逐记录调用通用字符串查找。新增短词预处理：单字节使用标准字符扫描，2–7 字节缓存词字节和首尾锚点，以安全的 8 字节块筛选候选，再完整比较。保持首次字节偏移；无 unsafe、填充读取或新依赖。长词 BMH/KMP 语义保持。
- 热记录由 104 字节缩为 56 字节；size/mtime/ctime/dev/inode/indexed_at 六个数值字段按块存储，普通数据每条另占 24 字节。使用 i128 检查差值与 31 位编码，任意 i64 极值和 NULL 保留。
- 不能压缩的值放入块内逃逸槽；同字段更新原槽、释放槽以内部链表复用，避免反复更新无限追加。容量超过完整 48 字节/条的数值载荷预算时，整块单向转为完整宽度并释放压缩载荷。容器头与字典额外计量，不能把 80 字节称为全部进程开销。
- 元数据变更不复制或增长字符串 arena；普通范围内更新也不增长元数据容量。极端数值变化允许有界元数据分配或按块转型，不能继续声称任意数值更新均零分配。增量预检的完整回退在修改前返回；异常沿用服务弃索引恢复契约。
- 增加只读容量组成诊断及通用短词基准工具，不更改索引数据库、偏好名称、默认模式、搜索上限和 GUI 行为。

## 正确性

- Debug/Release 各 107 项单测、420 次混合事务集成差分通过；每次事务将完整 FileRecord 及九类查询对照同一快照的新建索引。增量、墓碑复用、主键变化、回滚与整理回退保持。
- 新增短词 1–7 字节、跨块/首尾偏移、截断、重复/重叠、NUL、Unicode 小写扩展及独立旧 scorer 的完整结果/排序差分；字节候选过滤含 10,000 次随机测试。未只针对 code 调整。
- 数值字段验证包含 i64 极值、NULL、精确编码边界、500 轮跨字段逃逸/释放/复用、按块转宽后完整值校验、载荷容量上限与普通更新容量不变。
- 严格 Clippy all-targets、格式/diff、Python 语法及 Swift GUI 回归通过。独立交叉复核未发现短词首偏移、越界、字段丢失、排序或逃逸表增长的阻断问题。
- 短词工具的合成 2,000 行 A/B、load-only 与逆序检查通过；服务工具已支持前后两版均为增量后端，2,000 行真实 HTTP 混合更新、并发及故障恢复通过。合成检查不作真实数据性能结论。

## 数据与测量方法

沿用前三轮冻结的 7,226,486 条真实索引，SHA256 `68bd22081af1eb5ec9164037407cb6c9c13349a7f8e460fa9aa682b3286b5b29`。所有进程使用独立 APFS 克隆，不写原始快照或 live DB。两版均为 packed；串行两轮 A/B/A，共四个基线、两个候选进程，limit=300。CPU 为固定工作消耗的处理器时间；完整 13 个记录字段、score、顺序及 NULL 逐查询编码并比较 SHA256。

原九类查询与新增 29 项短词组分别测量。短词组包含 1–7 字节不同常见/低频词、code、六类 Unicode、纯通配符和原长词无命中查询；低频标签不预言零命中，报告以实际 count 为准。查询 CPU 不计结果 JSON/诊断，进程 RSS 峰值则包含整个加载/查询/序列化生命周期。内核缓存不清空，其他用户后台任务保留。

## 短词改动的独立验证

为区分 matcher 与存储布局影响，先用基线 packed 布局、只替换 search.rs 构建候选。code 单查询、两轮 A/B/A 的完整有序结果全部一致；CPU 中位数 378.88→190.03 ms（-49.8%），按前后基线配对中位数 -52.6%。全部样本保留，包含一个 478 ms 的基线样本。该实验只证明单独 matcher 的收益，最终结论仍以合并制品的两组测量为准。

## 真实容量组成

候选单独加载同一克隆得到 111 个窄块、0 个完整宽度块、157,914 个实际逃逸值；记录容量 407,371,776 B、元数据 176,194,432 B、字符串容量 1,744,830,464 B（已用 1,733,056,204 B）、扩展字典 38,014 B、容器 150,432 B，总计 2,328,585,118 B。字符串仍占主要部分，本轮不改变路径存储或引入可能影响匹配的目录分段。

前三轮首次文本查询后 RSS 上涨，随后基本平台；本轮只读 vmmap 显示主要为大型分配，未观察到 swap。无法仅由 RSS 跳变确定泄漏或纯查询临时分配。容量、RSS、physical footprint 和生命周期峰值分别保留，不相互替代。

| --- | ---: |
| ASCII 2–7 字节，18 项 | 降低 32.0%–60.3% |
