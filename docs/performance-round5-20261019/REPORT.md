# MacEvery 第五轮：原路径前缀共享与内存验收

2026-10-19，r2。受控正确性、CPU/RSS、App 原位替换、原生搜索和索引更新验收已完成。

## 改动与范围

基线源码为 `eeac95e`，其生产代码与替换前运行的 `0.1.3-gd62aa1d` 一致。继续使用前四轮同一个 7,226,486 条冻结快照，SHA256 `68bd22081af1eb5ec9164037407cb6c9c13349a7f8e460fa9aa682b3286b5b29`；每个进程使用独立克隆，不写真实索引。

`src/compact_index.rs` 保持小写完整路径及小写 basename 连续，查询扫描和短词 matcher 不变。原路径改为共享目录前缀加连续后缀；后缀与已有小写字符串相同时直接复用。热记录仍为 56B，新增前缀 ID 使用已有对齐空间。

`src/search.rs` 的 TopK 按两段拼接后的原始字节序、完整字节长度及既有稳定索引比较；扫描中不分配完整原路径，只为最终结果拼接。独立 basename、显式 lower、NULL/空 lower 回退和 Unicode 原值均保留。

前缀池只追加，实际保留的字符串和两张表连同池头受 64MiB 限制；满后新前缀的记录保留原始存储，既有前缀继续共享。删除后的共享字典不做引用回收，行碎片仅计独占字符串，现有增量 ID、墓碑和安全回退契约不变。扩容会短暂保留新旧表，64MiB 不是整个分配过程的峰值承诺。

- Debug/Release 各 114 项单测、420 次事务全记录差分和新增定向 prefix 更新集成测试通过；严格 all-target Clippy、格式、Python 与 GUI 取消/限流/子进程回收回归通过。
- 新夹具覆盖共享前缀删除/复活、重命名、主键变化、替换隐藏删除、低位 ID 干净回退、非后缀/超长 basename、NULL/空/独立 lower、Unicode 组合/分解、NUL、跨段原路径排序和池容量边界。
- 原九类和 29 项短词组分别做两组 A/B/A，共各 6 个独立进程；双方 packed，limit=300，fixed-now=1792195200，query-rounds=1，5ms 采样，完整有序结果字段和 score 哈希全部一致。真实大库哈希覆盖每次返回的最多 300 条，夹具承担全记录边界验证。
- 预设门禁：短词组及两个位置的 code 配对 CPU 中位数最多 +5%；任一词连续两块超过 +10% 且 +5ms 则调查。实际 fresh code −11.89%、hot code +1.77%、短词组 −0.42%，无重复明显回退项，全部通过。

原始诊断工具首次格式检查失败已修复，系统 Python 缓存路径的沙箱限制已适配；失败记录保留，未改变生产源码。进程采样适配 macOS ps 列宽与其他进程的非 UTF-8 参数，不将无效采样当作结果。

## CPU 与内存比较

以下是同组位置的普通中位数；配对变化另存结构化证据。RSS 是进程指标，容量是索引自有容器分配，两者不互换。

| 指标 | 第四轮基线 | 第五轮 | 变化 |
| --- | ---: | ---: | ---: |
| 索引分配容量（十进制 GB） | 2.329 | 1.537 | −34.0% |
| 九类负载加载后 RSS（GiB） | 1.689 | 1.130 | −33.1% |
| 九类负载生命周期峰值 RSS（GiB） | 2.502 | 1.537 | −38.6% |
| 首次 code 查询 CPU（ms） | 194.12 | 175.51 | −9.6% |
| 九类累计查询 CPU（秒） | 1.507 | 1.467 | −2.6% |
| 29 项短词累计 CPU（秒） | 5.861 | 5.857 | 基本持平 |
| 短词组热 code CPU（ms） | 148.67 | 151.84 | +2.1% |
| 九类组加载 CPU（秒） | 4.774 | 5.404 | +13.2% |

短词组的 RSS 结果也约为加载后 −33.1%、生命周期峰值 −38.6%；加载 CPU 4.708→5.144 秒（+9.3%）。保留回退：单字节 `e` +2.1%、`z` +4.4%（约 +10.62ms），九类 nohit/glob/Unicode 约 +1%。不宣称所有查询提速或加载加速。首次 code 是九类第 2 项，热 code 是短词组第 10 项，不能跨组位置比较。

容量八项合计精确为 2,328,585,118→1,537,288,452B。候选记录 407,371,776B、数值元数据 176,194,432B、字符串 arena 889,192,448B、前缀 payload 51,758,742B、前缀条目表 8,388,608B、查找表 4,194,304B、扩展字典 38,014B、其余容器 150,128B；468,666 个共享前缀。前缀三项合计 64,341,654B（61.36MiB），所有开销均计入，原字段/记录容量未减少或省略。

唯一父目录很多且 basename 很短的数据可能增加字典开销，池容量有界，不能从本快照推断所有分布都会节省相同内存。加载 CPU 上升是本轮降低内存的取舍。系统缓存未清空、其他用户应用保持运行；样本、单项变化和失败均保留。

## 索引更新与服务

`tools/check_service_round5.py` 复用既有 HTTP oracle，使用共享的 mixed-case 原路径探针。真实快照加两探针，两个版本 13 个阶段的六字段 HTTP 返回及 score/顺序一致；完整 lower/ctime/dev/inode 等由 Rust 差分覆盖。

正常三波各更新 1,000 普通记录并混合探针重命名、删除/插入、同 ID 替换及主键变化，full reload=0、incremental applies=1/2/3。HTTP 每波另核对一个普通行，不把它称为全 1,000 行的完整 HTTP oracle。状态读取观察 stale 而不触发刷新；显式 reload、4,097 事件超限、日志断档/缺失、读取失败 503 后恢复均通过。

40 并发两版均 2 个正确 200、38 个明确 busy503；health/status 与请求窗口重叠且成功，自有进程组/端口/临时副本清理通过。该固定 A 后 B 的服务生命周期峰值 RSS 2.503→1.538GiB；CPU 25.15→27.16 秒（+8.0%），含多次完整重载及故障恢复，只作机制观测，不能替代重复 A/B/A 或长期验收。

30 万条受控索引的真实 FSEvents A/B/A，九类文件/目录生命周期、排除目录写入及后续恢复均通过，最终状态一致。watch CPU 基线 0.02145/0.02559 秒，候选 0.02497 秒，峰值均约 11.19MiB；不声称 watcher CPU 获得稳定改善。
